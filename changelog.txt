Enchanter v1.7.1
----------------
- Fixed multi-enchant requests only responding to one enchant when another valid alias came from updated/custom Options data.
- Known recipes now compile their current configured aliases every load instead of relying on alias data saved by the last /ec scan.
- Prevented duplicate recipe mappings when multiple aliases normalize to the same phrase.
- Requests such as "LF +7 agi gloves and minor speed to boots" can now match and send materials for both known enchants.
- Fixed numeric enchant requests falsely matching a lower/generic enchant you actually know.
- A request such as "+9 strength to bracer" will no longer match the plain "Strength bracer" alias and trigger an invite when Superior Strength is unknown.
- Numeric requests now require the matching numeric recipe alias before Enchanter can whisper or auto-invite.


Enchanter v1.7.0
----------------
- Fixed material whispers being missing for some enchants when reagent item links were not cached.
- Material scanning now always uses the reagent API name/count as a fallback.
- Clickable reagent links are still used when available, and later scans can upgrade uncached links automatically.

Enchanter v1.6.9
----------------
- Fixed specific requests for enchants you do not know incorrectly falling through to the generic LF Enchanter whisper.
- Enchanter now checks the full configured Classic enchant alias list before sending the generic "What enchant you looking for?" response.
- Specific known enchant + recipe known: normal enchant/material response. Specific known enchant + recipe unknown: no automatic reply. Generic LF Enchanter only: generic prompt.
-Audited all 131 Classic Era enchant alias entries.
-Fixed incorrect aliases for Mighty Spirit (+20 Spirit), Mighty Intellect (+22 Intellect), and 2H Weapon – Agility (+25 Agility).
-Removed previously shipped incorrect numeric aliases from SavedVariables.
-Preserved existing user-created custom aliases.
-Checked alias generation for incorrect values, conflicts, and unsafe matches.

Enchanter v1.6.8
----------------
- Fixed tipped enchant trades sometimes being journaled as 0c when the zero-tip fallback ran before WoW updated the player's wallet.
- Added a login status message when Enchanter is enabled and listening.
- The status message is only shown on an actual character login, not on /reload.
- Journal now records each customer's class and displays their name using the standard WoW class colour.
- Fixed zero-tip completed enchant trades not always appearing in the Journal; completed trades are now logged even when no gold is given.
- Added the Enchanter Journal: a dedicated trade-history window showing date/time, player, enchant and gold made.
- /ec history now opens the Journal instead of printing session history to chat.
- Middle-clicking the minimap button now opens the Journal; recipe scan remains on Shift + Left-click and /ec scan.
- Expanded rolling enchant trade history from 200 to the latest 1,000 completed trades.
- Completed enchant trades with no tip are now retained in the Journal as 0c instead of being omitted.
- Lifetime trade and gold totals remain independent of Journal pruning.

## 1.6.6

### LF Enchanter Improvements
- Removed the automatic no-enchant reply for unmatched customer requests so misspellings and shorthand can be handled manually.
- Added configurable manual no-enchant phrases and a configurable manual rejection cooldown.
- Added outgoing-whisper detection so using a configured rejection phrase places that customer on the longer LF Enchanter cooldown.
- Kept the normal LF Enchanter anti-spam cooldown separate from the manual rejection cooldown.

### Enchant Matching
- Expanded default aliases across the Classic Era enchant list to recognize more natural player shorthand and common stat/slot wording.
- Added upgrade-safe alias merging: new built-in aliases are merged into SavedVariables without deleting aliases users have added themselves.
- Duplicate aliases are filtered case-insensitively during the merge.

### Options
- Widened the Search Patterns label column so longer option names and notes are no longer cut off.
- Kept the overall row width within the existing options panel by resizing the corresponding input fields.
